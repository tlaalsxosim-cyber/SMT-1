# AI 기반 일일 배송 최적화 시스템

출고등록현황(일일 변동)과 차량 톤수 마스터(고정)를 업로드하면, 기사 9명·총 12회전에 대한
배차 코스를 자동 편성하는 웹 앱입니다. **데이터베이스를 쓰지 않는 무저장(stateless) 구조**로,
입력은 매회 업로드하는 엑셀 2개가 전부이고 출력은 다운로드하는 엑셀 1개가 전부입니다.

- 기획서: [`docs/plan.md`](docs/plan.md)
- 요구사항 명세: [`docs/PRD.md`](docs/PRD.md) — 아래 코드 주석의 `FR-xx` / `R-xx` / `AC-xx` / `OI-x`는 모두 이 문서를 가리킵니다

## 빠른 시작

```bash
npm install
cp .env.example .env.local   # 키가 없어도 Demo Mode로 전부 동작합니다
npm run dev                  # http://localhost:3000
```

1. **데이터 업로드** 탭에서 `docs/출고등록현황.xlsx` 와 `docs/차량 톤수.xlsx` 를 함께 올립니다
2. **파일 검증 · 미리보기** — 파싱 지표, 원문/해석 대조, 담당자 확인 목록을 확인합니다
3. **배차 실행** — 기본값은 Demo Mode라 TMAP을 호출하지 않습니다
4. **배차 보드**에서 지도·기사별 티켓·기타(미배차)를 검토하고 **결과 엑셀**을 내려받습니다

> 결과를 내려받기 전에 페이지를 벗어나면 사라집니다. 무저장 구조에서 의도된 동작이며,
> 이탈 시 브라우저 경고가 뜹니다.

## 3계층 역할 분담

PRD §9의 분리를 그대로 코드 구조로 옮겼습니다.

| 계층 | 책임 | 위치 |
|---|---|---|
| ① 생성형 AI | 비정형 텍스트 해석·분류 | `src/lib/structure/llm.ts`, `enrich.ts` |
| ② 자체 로직 | **차량 간 배분** — 적재·회전·업체수·권역·조기납품 | `src/lib/dispatch/` |
| ③ TMAP | 좌표·방문순서·실도로 경로 | `src/lib/tmap/` |

`src/lib/pipeline/run.ts` 가 세 계층을 순서대로 엮습니다.

```
[1] 파싱·검증 → [2] 조건 구조화 → [3] 좌표 변환 → [4] 차량 간 배분
  → [5] 방문순서 최적화 → [6] 시간 검증(위반 시 [4] 복귀) → [7] 경로 확정 → [8] 출력
```

### 왜 규칙 파서가 먼저인가

AI는 규칙 파서를 **대체하지 않고 보완**합니다. 2026-09-15 실데이터 기준으로 규칙만으로
55곳 중 45곳의 시간창을 확보하며, AI에는 규칙이 해석하지 못했거나 두 소스가 어긋난 건만
보냅니다. AI 출력은 구조화 JSON으로 받고 `validateWindows` 검증을 통과해야 배차에
반영되며, 확신도가 낮으면 담당자 확인 목록으로만 보냅니다.

키가 없으면 AI 단계를 건너뛰고 규칙 기반으로만 동작합니다.

## 실데이터에서 드러난 것들

`docs/` 의 2026-09-15 실파일을 전수 검사한 결과가 코드와 테스트에 고정되어 있습니다.

| 항목 | 값 |
|---|---|
| 오더 행 | 304 → 배차 대상 287 (픽업 12 · 취소 4 · 이체 1 제외) |
| 납품처 | 55곳 / 8,043박스 |
| 차량 | 9명 · 12회전 · 적재 상한 8,225 · 업체 수 상한 42 |
| **구조적 미배차** | **최소 13곳** — 납품처 55곳 > 업체 수 상한 42곳 |

**적재량(8,043 / 8,225)은 빠듯하게 맞지만 업체 수가 먼저 막힙니다.** 이 시스템의 역할은
"전량 배차"가 아니라 제약을 지킨 최적 조합을 만들고 남는 물량을 사유와 함께 드러내는 것입니다.

### 납품시간 컬럼만 믿으면 시간 위반이 납니다

컬럼과 납품처명 원문이 6건 어긋납니다. 두 소스를 대조해 **더 엄격한 쪽**을 채택합니다.

| 업체 | 원문 | 컬럼 | 문제 |
|---|---|---|---|
| 지케이(광주새말길) | `8~15시(12시30분~13시30분제외)` | `8:00~17:00` | 마감 2시간 과대 |
| 동원홈푸드(화성센터) | `8:30~13:00` | `8:30~14:00` | 마감 1시간 과대 |
| 삼성웰스토리 · 신의유통 · 원앤원 · 지키미에프에스 | 시간 조건 있음 | (비어있음) | 제약 전량 유실 |

점심 등 배제 구간은 시간창 2개로 분리합니다 — `8~11또는13~14:30(점심11:30~13)` →
`08:00~11:00, 13:00~14:30`.

## Demo Mode

경유지 최적화 API는 **하루 50건**이 전부입니다. 개발·시연 중 버튼을 몇 번만 눌러도
당일 운영분이 사라지므로, TMAP을 전혀 호출하지 않고 전 과정을 재현하는 모드를 기본값으로 둡니다.

- 좌표: 시·군 중심점 + 주소 해시 기반 결정적 산포 (같은 주소는 항상 같은 좌표)
- 방문순서: 최근접 이웃 + 2-opt (귀가 구간 포함 총거리 최소화)
- 거리: 직선거리 × 도로 우회 계수 1.35

운영 모드에서도 보호 장치가 겹쳐 있습니다.

- 회전당 최적화 1회, 재시도 1회 한도 (R-11)
- 안전 상한 24건/일, 무료 한도 50건 도달 시 차단 (`assertOptimizeBudget`)
- 배차 실행 **서버 측 잠금** — 버튼 연타·새로고침 연타를 409로 거부 (FR-33)
- 설정 탭의 일일 호출 카운터

## 무저장 구조가 코드에서 지켜지는 방식 (NFR-01)

- 데이터베이스·ORM·마이그레이션 없음. 파일 시스템에도 쓰지 않습니다
- `localStorage` / `sessionStorage` / IndexedDB 미사용 — `drive-ui` 시나리오가 항목 0개를 검증합니다
- 서버는 요청 처리 중에만 메모리에 들고, 응답 후 버립니다
- API 호출 카운터만 서버 프로세스 메모리에 남고, 재시작하면 0으로 돌아갑니다 (화면에 명시)
- TMAP 경로 좌표를 24시간 이상 보관하지 않으므로 약관과 자연스럽게 부합합니다 (NFR-02)

키는 환경변수로만 관리하며, 설정 화면은 **존재 여부만** 표시하고 값은 내보내지 않습니다 (NFR-03).
TMAP 호출은 전부 서버 라우트를 경유합니다 — 브라우저 직접 호출은 CORS에 막히고 키가 노출됩니다.

## 구현 결정과 미확정 사항

### 기획서와 다르게 구현한 부분

**2회전 차량의 1회전 도착지** — PRD §2.2⑤는 모든 회전의 도착지를 기사 거주지로 지정하지만,
2회전 차량의 1회전은 **평택센터로 복귀해 재상차한 뒤 다시 출발**합니다. 그래서 **마지막 회전만
도착지를 기사 거주지로, 그 앞 회전은 센터로** 둡니다. 이렇게 해야 귀가 거리와 2회전 출발
시각이 모두 맞습니다. (현업 확정 완료 · `src/lib/dispatch/assign.ts` 상단 주석)

**TMAP 도착예정시각에 대기 반영** — TMAP `arriveTime`은 주행 시간만 계산합니다. 시간창이
열리기 전에 도착하면 기사는 기다렸다 하차하고 이후 배송지가 그만큼 밀립니다. 이 보정을 하지
않으면 "일찍 도착"이 시간창 위반으로 잘못 잡혀 멀쩡한 배송지가 무더기로 기타로 빠집니다.
(`src/lib/dispatch/waiting.ts`)

**지도** — TMAP Map JS(jsv2)는 브라우저에 App Key를 실어야 합니다. 서버 프록시로 감쌀 수 없으므로
운영 키(`TMAP_APP_KEY`)를 쓰지 않고, **도메인 제한을 건 별도 웹 키** `NEXT_PUBLIC_TMAP_WEB_KEY`가
있을 때만 jsv2를 띄웁니다. 키가 없거나 SDK 로딩에 실패하면 외부 호출이 전혀 없는 내장 SVG 지도로
자동 전환하고 사유를 화면에 표시합니다. 마커·경로선·클릭 팝업·자동 범위 조절은 양쪽이 동일합니다.

jsv2는 부트스트랩이 SDK 본체를 `document.write`로 붙이는 구조라, 동적으로 추가한 스크립트에서는
브라우저가 그 호출을 무시합니다. `src/components/tmap-sdk.ts`가 `document.write`를 잠깐 가로채
본체를 직접 붙여 이 문제를 피합니다. 타일은 기본 프로토콜이 http라 HTTPS 배포에서 Mixed Content로
차단되므로 지도 생성 옵션에 `httpsMode: true`를 넣습니다.

설정 방법:

1. SK open API 콘솔에서 **운영 키와 별개인 앱**을 만들고 App Key를 발급받습니다
2. 해당 앱의 보안 설정에서 웹 서비스 URL을 제한합니다 (개발 `http://localhost:3000`, 운영은 실제 도메인)
3. `.env.local`에 `NEXT_PUBLIC_TMAP_WEB_KEY=발급받은키`를 넣습니다
4. **개발 서버를 재시작합니다** — `NEXT_PUBLIC_` 값은 빌드 시점에 인라인되므로 재시작 없이는 반영되지 않습니다

설정 여부는 설정 탭의 「키 상태」에서 확인할 수 있습니다.

### 확정 완료 (2026-09-16)

- **OI-9 · 회전 간 동선** — 2회전 차량의 1회전은 평택센터로 복귀해 **재상차한 뒤 다시 출발**합니다.
  따라서 마지막 회전의 도착지만 기사 거주지이고, 그 앞 회전의 도착지는 센터입니다.
- **OI-10 · 조기납품 제한** — 제약은 **한 기사에게 조기납품 업체를 2곳 이상 배정하지 않는 것** 하나뿐입니다.
  회전 번호는 제약이 아니며, 2회전에 조기납품을 넣을 수 있는지는 시간 실현성(R-09)이 판단합니다.
- **R-15 · 2회전 납품 마감 하한 = 15:00 확정** — 센터 복귀 후 재출발하는 회전에는
  **마감이 15:00보다 이른 업체를 배정하지 않습니다.** 확정된 업무 규칙이라 상수로 고정했고
  화면에서 바꿀 수 없습니다. 시간 제약이 없는 업체는 허용하고, 1회전에는 적용하지 않습니다.
- **R-16 · 납품 시작 시각** — **등록된 업체는 등록값 그대로**(08:30·09:00·09:30·11:00·11:30 …),
  「13시착」처럼 **누락된 업체만 08:00**으로 채웁니다. 실데이터 기준 등록 20곳 / 누락 25곳이며,
  `npm run start-check`가 업체별 적용 결과와 "등록값이 덮인 건 0" 검증을 출력합니다.

- **R-17 · 대형차는 회전당 1업체** — 5톤 이상 차량은 한 회전에 업체 한 곳이 원칙이고,
  2번째 업체는 **주소가 거의 동일할 때만**(층·도크·건물명을 뺀 도로명/지번이 일치) 붙입니다.
  차량 마스터의 `최대업체수`(5·10톤 = 2)는 *같은 건물에 업체가 둘일 때의 상한*이지
  아무 두 곳이나 묶어도 된다는 뜻이 아닙니다. R-03(적재 하한)과 맞물려
  **적재 하한 미만의 소량 업체는 대형차에 배차되지 않습니다** —
  2026-09-15 결과에서 지적된 `원앤원 30박스 + 하림충북 1,061박스`가 이 규칙으로 갈라집니다.
- **R-18 · 천안 이남은 지입 배차에서 제외** — 후순위가 아니라 **제외**입니다. 위도 36.9(천안 포함)
  미만은 배차 대상 풀에서 아예 걷어 내고, 사유 「수도권외」로 기타에 남겨 **용차 판단으로
  넘깁니다**(R-12). 초과 물량 분할(R-06)보다 먼저 적용하므로 남쪽 대형 건은 쪼개지지 않고
  한 줄로 남습니다.

  처음에는 점수 벌점(후순위)으로 만들었는데, 북쪽에 대안이 없으면 그대로 배차돼 버렸습니다 —
  실데이터가 정확히 그랬습니다(익산 1,200 · 청주 1,061). 그래서 제외가 아니면 의미가 없습니다.
